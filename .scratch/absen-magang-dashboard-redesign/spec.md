# Redesain Dashboard Pengurus Absen PL — Admin Panel & Mobile Friendly

## Problem Statement

Setelah redesign gerbang (`/login`, `/daftar`, `/absen`, lihat `.scratch/absen-magang-gerbang-visual/spec.md`), area `/dashboard/*` yang dipakai Pengurus sehari-hari (Beranda, Pendaftaran, Jendela Absen, Kehadiran Ditinjau, Laporan) sengaja tidak disentuh dan masih memakai styling generik paling dasar dari `globals.css`: satu `<nav>` flex-wrap berisi lima link teks polos, tabel HTML mentah untuk Pendaftaran dan Kehadiran Ditinjau (7 dan 6 kolom), form tanpa struktur visual, dan halaman Beranda yang hanya berisi satu paragraf ("pilih menu di atas"). Tidak ada perlakuan khusus untuk layar sempit di luar `flex-wrap` pada nav — tabel berkolom banyak tidak terbaca di HP, dan Pengurus yang membuka dashboard dari HP (yang dikonfirmasi terjadi, lihat spec Absen PL User Story 12) tidak punya cara nyaman menavigasi atau membaca data. Pengurus sudah senang dengan tampilan gerbang yang baru dan ingin area dashboard mendapat perlakuan setara: rapi, mengikuti identitas visual surau lewat token yang sama, dan nyaman dipakai dari HP maupun desktop.

## Solution

Bangun satu admin-panel shell baru khusus `/dashboard/*` — berbeda dari `GerbangShell` bermerek yang dipakai gerbang, karena area ini data-heavy dan dipakai berulang tiap hari, bukan layar auth sekali pakai. Shell ini terdiri dari sidebar navigasi tetap di desktop (lima link + info Pengurus dan tombol keluar di footer sidebar) yang di layar sempit berubah jadi drawer slide-out dibuka lewat tombol hamburger pada top bar ringkas (hanya berisi hamburger + judul halaman). Kelima halaman existing dipertahankan strukturnya (tidak ada penggabungan/pemecahan rute, tidak ada perubahan field/logika) tapi direstyle memakai komponen `ds/` yang sudah ada (`Card`, `Button`, `Input`, `Badge`, `Icon`) plus komponen baru yang dibutuhkan pola admin panel ini (`Sidebar`/nav item, `StatCard`, wrapper tabel yang runtuh jadi kartu di layar sempit). Halaman Beranda naik level dari paragraf statis menjadi ringkasan nyata: tiga kartu statistik (Pendaftaran menunggu, Kehadiran perlu ditinjau, Peserta aktif) yang masing-masing tertaut ke halaman terkait, memakai fungsi `lib/absen` yang sudah ada tanpa query database baru. Perubahan ini murni pada lapisan presentasi `/dashboard/*` — tidak ada perubahan pada `lib/absen/*`, skema database, session/auth, maupun `actions.js` di rute manapun.

## User Stories

1. As Pengurus, I want membuka `/dashboard` dan langsung melihat ringkasan berapa Pendaftaran yang menunggu keputusan saya, so that saya tahu ada pekerjaan yang perlu saya selesaikan tanpa harus membuka halaman Pendaftaran dulu.
2. As Pengurus, I want melihat di Beranda berapa Kehadiran yang berstatus ditinjau, so that saya tahu ada kasus check-in/check-out di luar Jendela Absen yang perlu saya putuskan.
3. As Pengurus, I want melihat di Beranda berapa Peserta yang statusnya aktif (Pendaftaran-nya sudah disetujui), so that saya punya gambaran skala operasional PL saat ini tanpa membuka halaman Laporan.
4. As Pengurus, I want mengetuk/klik kartu statistik di Beranda dan langsung diarahkan ke halaman terkait (Pendaftaran, Kehadiran Ditinjau), so that ringkasan itu jadi jalan pintas kerja, bukan cuma angka pajangan.
5. As Pengurus di desktop, I want melihat sidebar navigasi permanen di sisi layar berisi kelima menu (Beranda, Pendaftaran, Jendela Absen, Kehadiran Ditinjau, Laporan), so that saya bisa berpindah menu tanpa scroll ke atas mencari link seperti sekarang.
6. As Pengurus di desktop, I want melihat username saya dan tombol Keluar di bagian bawah sidebar, so that saya tahu akun mana yang sedang login dan bisa logout tanpa mencarinya di tempat lain.
7. As Pengurus yang membuka dashboard dari HP, I want melihat top bar ringkas berisi tombol hamburger dan judul halaman yang sedang dibuka, so that saya tetap tahu saya sedang di halaman mana tanpa sidebar memenuhi layar sempit saya.
8. As Pengurus di HP, I want mengetuk tombol hamburger dan melihat sidebar yang sama (lima menu + username + tombol Keluar) muncul sebagai drawer, so that navigasi saya di HP identik isinya dengan di desktop, hanya beda cara memunculkannya.
9. As Pengurus di HP, I want drawer navigasi tertutup lagi setelah saya memilih satu menu atau mengetuk area di luar drawer, so that saya langsung melihat halaman yang saya pilih tanpa langkah tambahan menutup drawer.
10. As Pengurus di HP yang membuka halaman Pendaftaran, I want melihat tiap calon Peserta sebagai satu kartu berisi semua field (nama, asal kampus, jurusan, NIM, WhatsApp, Periode PL) dan tombol Setujui/Tolak, bukan tabel yang harus digeser ke samping, so that saya bisa membaca dan memutuskan Pendaftaran tanpa scroll horizontal yang merepotkan.
11. As Pengurus di desktop yang membuka halaman Pendaftaran, I want tetap melihat data itu sebagai tabel biasa (bukan kartu), so that saya bisa membandingkan banyak baris sekaligus seperti kebiasaan kerja saya di layar lebar.
12. As Pengurus yang menyetujui sebuah Pendaftaran, I want tetap melihat PIN yang di-generate ditampilkan jelas di kartu/baris Peserta itu setelah keputusan saya, so that saya tetap bisa langsung menyalin dan menyampaikannya ke Peserta secara manual seperti alur sekarang.
13. As Pengurus di HP yang membuka halaman Kehadiran Ditinjau, I want melihat tiap Kehadiran sebagai satu kartu berisi nama Peserta, tanggal, jam masuk/pulang, info lokasi check-in dan check-out, serta tombol Setujui/Tolak/Koreksi jam, so that saya bisa meninjau dan memutuskan tanpa tabel sempit yang memotong informasi lokasi.
14. As Pengurus di desktop yang membuka halaman Kehadiran Ditinjau, I want tetap melihat data itu sebagai tabel, so that pola kerja saya di layar lebar tidak berubah.
15. As Pengurus yang memilih "Koreksi jam" pada sebuah Kehadiran (baik di tampilan tabel maupun kartu), I want tetap bisa mengubah jam masuk/pulang lewat input datetime dan menyimpannya seperti alur yang sudah ada, so that kemampuan koreksi saya tidak hilang akibat redesign.
16. As Pengurus yang membuka halaman Jendela Absen, I want melihat form pengaturan lokasi + jam kerja dalam tata letak yang rapi dan konsisten dengan halaman lain (pakai `Card`/`Input`/`Button`), so that halaman ini terasa satu keluarga visual dengan seluruh dashboard, bukan form polos berbeda gaya.
17. As Pengurus yang membuka halaman Laporan, I want melihat form pilih Peserta + rentang tanggal dalam tata letak yang rapi dan mobile-friendly, so that saya bisa men-generate Laporan PDF dengan nyaman baik dari desktop maupun HP.
18. As Pengurus, I want seluruh halaman dashboard (Beranda, Pendaftaran, Jendela Absen, Kehadiran Ditinjau, Laporan) tetap berfungsi identik secara logika seperti sebelumnya (field, validasi, hasil aksi Setujui/Tolak/Koreksi/Generate PDF, redirect setelah logout, dst), so that pekerjaan harian saya tidak terganggu oleh redesign yang murni visual/struktural.
19. As Pengurus, I want halaman dashboard yang sedang saya buka ditandai jelas (mis. highlight) di sidebar/drawer, so that saya selalu tahu posisi saya di dalam lima menu itu.
20. As Pengurus, I want tombol Keluar tetap berfungsi seperti sekarang (memanggil `logoutPengurus` lalu diarahkan keluar sesi), so that logout saya tidak berubah perilakunya akibat pemindahan posisi tombol ke sidebar.
21. As Pengurus yang membuka halaman manapun di dashboard tanpa item pada daftar (mis. tidak ada Pendaftaran menunggu, tidak ada Kehadiran ditinjau), I want melihat pesan kosong yang rapi dan konsisten gaya dengan redesign ini (bukan cuma teks polos seperti sekarang), so that halaman kosong tidak terasa seperti bug atau halaman belum jadi.
22. As pengelola sistem, I do NOT want ada perubahan pada `lib/absen/*`, skema database, session/auth Pengurus, atau `actions.js` di rute manapun di bawah `/dashboard`, so that seluruh perilaku domain (Pendaftaran, Kehadiran, Jendela Absen, Laporan, logout) persis sama seperti sebelum redesign.
23. As pengelola sistem, I want komponen baru yang dibutuhkan pola admin panel (sidebar/nav item, kartu statistik, wrapper tabel-jadi-kartu) ditambahkan ke `absen-magang/components/ds/` mengikuti pola komponen yang sudah divendor di sana (`Button`, `Card`, `Input`, `Badge`, `Icon`), so that dashboard konsisten secara arsitektur dengan redesign gerbang sebelumnya, bukan styling ad hoc per halaman.
24. As pengelola sistem, I want `next build` produksi tetap sukses setelah perubahan ini, so that redesign tidak memperkenalkan regresi build.
25. As pengelola sistem, I want kelas CSS lama di `globals.css` (`.card`, `button`/`.secondary`/`.danger`, `.error`/`.success`, `.status-badge`, `.modal-overlay`/`.modal-card`) tetap ada apa adanya karena masih dipakai `LokasiModal` di `/absen`, so that redesign dashboard tidak menimbulkan regresi di halaman gerbang yang sudah selesai.

## Implementation Decisions

- **Lingkup**: seluruh halaman di bawah `/dashboard` — Beranda (`dashboard/page.jsx`), Pendaftaran, Jendela Absen, Kehadiran Ditinjau, Laporan — plus `dashboard/layout.jsx` yang membungkus semuanya. `/login`, `/daftar`, `/absen` (gerbang) di luar lingkup, sudah selesai di spec sebelumnya.
- **Shell admin panel baru** (bukan `GerbangShell`): komponen shell baru (mis. `DashboardShell`) menggantikan isi `dashboard/layout.jsx` saat ini yang hanya berupa `<main className="container"><nav>...`. Terdiri dari:
  - **Sidebar** (desktop): lebar tetap, selalu terbuka penuh (tanpa toggle collapse-ke-ikon), berisi lima link nav (Beranda, Pendaftaran, Jendela Absen, Kehadiran Ditinjau, Laporan) dengan indikator halaman aktif (mis. berdasarkan `usePathname`), dan footer sidebar berisi username Pengurus (dari `session.username`, sudah tersedia di layout saat ini) + tombol Keluar yang tetap memanggil `logoutPengurus` lewat form action seperti sekarang.
  - **Top bar** (mobile, di bawah breakpoint tertentu): hanya tombol hamburger + judul halaman aktif, tanpa duplikasi username/logout.
  - **Drawer** (mobile): dibuka oleh tombol hamburger, menampilkan sidebar yang identik (lima link + footer username/logout), tertutup otomatis saat satu link dipilih atau area di luar drawer diketuk.
  - Breakpoint switch sidebar-tetap ↔ drawer-mobile bebas ditentukan tim implementasi (CSS media query atau deteksi lebar viewport, konsisten dengan pendekatan breakpoint yang sudah dipakai di redesign gerbang).
- **Judul halaman untuk top bar**: tiap halaman dashboard menyediakan judulnya sendiri ke shell (mis. lewat prop, atau shell menerima nama halaman dari konteks route) — dipetakan langsung dari `<h1>` yang sudah ada di tiap halaman (`Dashboard Pengurus`, `Pendaftaran Menunggu`, `Jendela Absen`, `Kehadiran Ditinjau`, `Generate Laporan`).
- **Beranda — kartu statistik**: `dashboard/page.jsx` diperluas memanggil tiga fungsi yang sudah ada di `lib/absen`: `daftarPendaftaranMenunggu` (hitung panjang array untuk "Pendaftaran menunggu"), `daftarKehadiranDitinjauDenganPeserta` (hitung panjang array untuk "Kehadiran perlu ditinjau"), dan `daftarPeserta` difilter di halaman (bukan query baru) ke `status_pendaftaran === 'disetujui'` untuk "Peserta aktif". Tidak ada fungsi baru ditambahkan ke `lib/absen`. Tiap kartu (komponen baru `StatCard` di `ds/`) menampilkan angka + label, dan jadi `Link` (Next.js) ke halaman terkait — "Pendaftaran menunggu" dan "Peserta aktif" ke `/dashboard/pendaftaran`, "Kehadiran perlu ditinjau" ke `/dashboard/kehadiran`.
- **Tabel → kartu di mobile** (Pendaftaran, Kehadiran Ditinjau): dibangun sebagai satu wrapper/pola bersama (mis. komponen atau util CSS `ResponsiveTable`) yang me-render `<table>` biasa di atas breakpoint dan kartu (satu per baris/entitas) di bawahnya — data dan handler tetap sama, hanya presentasinya beda per breakpoint. `PendaftaranRow` dan `KehadiranRow` (dan turunannya, `BarisLokasi`) direstrukturisasi agar bisa dipakai kedua mode ini tanpa duplikasi logika (state `keputusan`/`koreksi`/`pin`, pemanggilan `setujuiPendaftaranAction`/`tolakPendaftaranAction`/`setujuiKehadiranAction`/`tolakKehadiranAction`/`koreksiKehadiranAction` semuanya tidak berubah). Tombol aksi (Setujui/Tolak/Koreksi jam) di mode kartu ditata full-width vertikal mengikuti pola `Button fullWidth` yang sudah dipakai di `/absen`.
- **Reveal PIN setelah Setujui** (Pendaftaran) tetap tampil inline di kartu/baris Peserta yang sama, tidak dipindah ke tempat lain (mis. modal terpisah) — perilaku dan penempatan pesan "PIN: ... — sampaikan ke Peserta secara manual" dipertahankan persis.
- **Komponen `ds/` baru yang ditambahkan** (mengikuti pola vendoring komponen yang sudah ada, lihat ADR 0016): `Sidebar`/nav-item (dipakai desktop sidebar dan mobile drawer, sumber data yang sama), `StatCard`, dan komponen/util untuk pola tabel-jadi-kartu. Komponen existing (`Card`, `Button`, `Input`, `Badge`, `Icon`) dipakai ulang, tidak diduplikasi.
- **Empty state**: pesan "Tidak ada Pendaftaran yang menunggu saat ini." / "Tidak ada Kehadiran berstatus ditinjau saat ini." direstyle memakai `Card`/`Icon` (pola empty-state ringan: ikon + teks), bukan lagi `<p>` polos, konsisten di kedua halaman.
- **Form Jendela Absen dan Laporan**: direstyle memakai `Card`/`Input`/`Button` yang sudah ada, mengikuti pola visual yang sama dengan form di gerbang (`/login`, `/daftar`) — field, validasi, dan `action` handler tidak berubah.
- **Ikon**: memakai `Icon` yang sudah ada (nama ikon Lucide bebas dipilih via CDN, tidak ada pembatasan daftar ikon).
- **Token & CSS**: seluruhnya memakai token yang sudah ada di `absen-magang/styles/tokens/` — tidak ada token/warna baru. Kelas CSS lama di `globals.css` yang masih dipakai `/absen` (`LokasiModal`) tidak diubah/dihapus; kelas/komponen baru untuk dashboard ditambahkan terpisah (file baru, mis. `styles/dashboard.css`, atau lewat komponen `ds/` yang stylingnya inline/CSS module — bebas ditentukan tim implementasi selama tidak memodifikasi kelas lama yang disebut di atas).
- **Highlight halaman aktif** di sidebar/drawer: berdasarkan pathname saat ini (`usePathname` dari `next/navigation`), dibandingkan ke `href` tiap link nav.

## Testing Decisions

- Tidak ada automated test baru — redesign ini murni presentasi (layout/CSS/markup), tidak menyentuh `lib/absen/*` yang merupakan satu-satunya lapisan dengan pola pengujian di repo ini (`lib/absen/*.test.js` via PGlite, menguji operasi domain, bukan komponen React/halaman). Precedent: `.scratch/absen-magang-gerbang-visual/spec.md` (redesign gerbang) memakai keputusan pengujian yang identik.
- Verifikasi: manual lewat browser untuk tiap acceptance criteria (user stories di atas), ditambah `next build` produksi sukses tanpa error.
- Skenario manual yang wajib dicek:
  - Beranda menampilkan tiga angka statistik yang benar (cocok dengan data di Pendaftaran/Kehadiran Ditinjau/daftar Peserta saat itu) dan tiap kartu mengarah ke halaman yang benar.
  - Sidebar desktop menampilkan lima link + username + tombol Keluar; highlight halaman aktif berpindah sesuai rute.
  - Di lebar viewport sempit (≈375px): top bar hanya hamburger + judul; drawer terbuka menampilkan isi sidebar identik; drawer tertutup otomatis setelah memilih link atau mengetuk di luar drawer.
  - Halaman Pendaftaran dan Kehadiran Ditinjau: tabel biasa muncul di lebar desktop, kartu per baris muncul di lebar mobile — kedua mode menjalankan aksi (Setujui/Tolak/Koreksi jam) dengan hasil yang sama seperti sebelum redesign, termasuk reveal PIN setelah Setujui Pendaftaran dan info lokasi (termasuk kasus "lokasi tidak terkirim") di Kehadiran Ditinjau.
  - Halaman Jendela Absen dan Laporan: seluruh field, submit, dan hasil (simpan pengaturan, buka PDF di tab baru) berfungsi seperti sebelumnya dengan tampilan baru.
  - Empty state tampil rapi saat daftar Pendaftaran/Kehadiran Ditinjau kosong.
  - Tombol Keluar di sidebar/drawer tetap memicu `logoutPengurus` dan mengarahkan keluar sesi seperti sebelumnya.
  - Halaman `/absen` (`LokasiModal` dan kelas CSS lama lainnya) tidak mengalami regresi visual akibat perubahan `globals.css`.

## Out of Scope

- Halaman gerbang (`/`, `/login`, `/daftar`, `/absen`) — sudah selesai di spec sebelumnya, tidak disentuh lagi di sini kecuali `globals.css` yang dipastikan tidak regresi.
- Perubahan apa pun pada `lib/absen/*`, skema database, session/auth Pengurus, atau `actions.js` di rute manapun.
- Query/fungsi database baru untuk statistik Beranda — ketiga angka dihitung dari fungsi `lib/absen` yang sudah ada, bukan agregasi baru di level database.
- Penggabungan atau pemecahan rute dashboard (kelima halaman tetap URL terpisah seperti sekarang).
- Mengganti `LokasiModal` custom di `/absen` dengan komponen `Dialog` design system (tidak relevan dengan lingkup dashboard).
- Notifikasi otomatis, fitur baru, atau perubahan alur bisnis apa pun di luar yang sudah ada (tetap sesuai Out of Scope spec Absen PL induk).
- Collapse-to-icon pada sidebar desktop, atau pola bottom-tab-bar untuk navigasi mobile (sudah diputuskan pakai hamburger+drawer).
- Automated test/visual regression baru (lihat Testing Decisions).

## Further Notes

- Spec ini adalah lanjutan dari `.scratch/absen-magang-gerbang-visual/spec.md` (redesign gerbang) — keduanya bersama menyelesaikan redesign visual penuh Absen PL (gerbang + dashboard), tapi dipisah jadi dua spec karena gerbang dan dashboard punya kebutuhan shell yang berbeda (bermerek/marketing vs admin-panel/fungsional) dan dikerjakan di sesi terpisah.
- Keputusan breakpoint spesifik (nilai piksel persis untuk switch sidebar↔drawer dan tabel↔kartu) sengaja tidak dipatok di sini — detail implementasi yang wajar diserahkan ke tim implementasi selama konsisten dan hasil akhirnya lolos skenario manual di atas.
- Nama komponen baru (`DashboardShell`, `Sidebar`, `StatCard`, dll.) adalah usulan penamaan, bukan nama final yang mengikat — tim implementasi bebas menyesuaikan selama perannya sesuai Implementation Decisions di atas.
