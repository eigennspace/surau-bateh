# Situs produksi memvendor snapshot design system, bukan mengimpor langsung

**Supersedes [0002](0002-production-imports-design-system-components-directly.md).** Situs produksi (`site/`) harus bisa di-build dan di-deploy secara independen, tanpa folder `New Surau Bateh Lori Design System/` hadir di sebelahnya — mis. untuk deploy dari sub-folder `site/` saja. Kami memutuskan situs menyalin (vendor) subset komponen, token CSS, `styles.css`, dan aset yang benar-benar dipakai runtime ke `site/src/design-system/`, lewat skrip `site/scripts/sync-design-system.mjs` (`npm run sync-ds`) yang dijalankan manual saat desain sumber berubah — bukan lagi impor relatif langsung ke folder design system, dan bukan paket npm terpisah (masih dalam repo yang sama, kontrolnya sama). Hasil vendor dikomit ke git supaya build tidak butuh folder design system hadir. Konsekuensinya: situs dan design system bisa drift secara visual di antara dua kali `sync-ds` — beda dengan jaminan "identik 100%" di ADR 0002 — dan pemelihara harus sengaja menjalankan `sync-ds` untuk menarik pembaruan desain. Berkas authoring design system (`*.prompt.md`, `*.d.ts`, `*.card.html`, `guidelines/`, `ui_kits/`, `uploads/`, dll) sengaja tidak ikut divendor — itu tetap milik skill design system, bukan dependency situs.
