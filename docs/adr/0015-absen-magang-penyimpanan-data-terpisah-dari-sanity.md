# Data kehadiran Absen PL disimpan terpisah dari Sanity, bukan sebagai tipe dokumen baru

Sejak ADR 0013, arah proyek ini adalah memindahkan seluruh konten yang bisa diedit pengurus ke Sanity. Absen PL (pencatatan kehadiran mahasiswi/intern PL) sengaja **tidak** mengikuti arah itu: datanya disimpan di database operasional milik aplikasi Absen PL sendiri (Postgres), bukan sebagai tipe dokumen Sanity baru dan bukan lewat dataset `production` yang sama.

Alasannya: Sanity di proyek ini dipakai sebagai CMS editorial — dokumen ditulis lewat Studio oleh pengurus, dipublish, lalu men-trigger rebuild statis situs (pengunjung situs publik tidak pernah menulis ke Sanity). Kehadiran sebaliknya adalah log operasional yang ditulis terus-menerus oleh Peserta sendiri lewat aplikasi terpisah yang berjalan sebagai layanan hidup (bukan static export) di subdomain sendiri. Memaksakan pola tulis Sanity Studio ke bentuk ini (record check-in/check-out harian, puluhan per hari) tidak cocok dengan cara Sanity dipakai di sisa proyek, dan akan mengikat siklus hidup data operasional Absen PL ke dataset editorial Situs Publik yang seharusnya tidak berhubungan.

**Konsekuensi**: Absen PL adalah bounded context terpisah (lihat `CONTEXT-MAP.md` dan `absen/CONTEXT.md`) dengan penyimpanan data sendiri; satu-satunya yang dipinjam dari proyek ini adalah token desain visual (`New Surau Bateh Lori Design System/`), bukan data atau infrastruktur Sanity.
