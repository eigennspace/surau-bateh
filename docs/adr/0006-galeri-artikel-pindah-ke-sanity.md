# Galeri & artikel dikelola lewat Sanity CMS, bukan lagi hand-edit `sourceData.js`/Markdown

**Menyempit [0001](0001-static-site-hand-edited-data-file.md).** Pengurus surau makin sering minta update foto dan artikel, dan setiap permintaan berarti maintainer situs harus mengedit kode, menjalankan test, dan mendorong perubahan lewat git — bottleneck yang tidak skalabel untuk konten yang makin sering berubah, dan pengurus tidak punya cara mandiri untuk memperbarui foto/artikel tanpa melibatkan maintainer.

Kami memutuskan memindahkan dua tipe konten yang paling sering diminta — **galeri foto** dan **artikel** — ke **Sanity** sebagai headless CMS, dengan arsitektur **build-time fetch**: situs tetap 100% static export ke GitHub Pages (tidak ada dependency runtime ke Sanity untuk pengunjung), konten ditarik dari dataset Sanity saat `vite build` lewat `@sanity/client`, dan publish oleh pengurus di Sanity Studio memicu webhook → GitHub Actions (`repository_dispatch`) yang menjalankan rebuild + deploy otomatis. Sanity dipilih di atas Decap CMS (UX/image handling lebih kasar) dan Payload (butuh server yang harus dioperasikan sendiri) — free tier hosted, image CDN/pipeline bawaan, Studio yang ramah untuk editor non-teknis.

Studio di-deploy terpisah ke `*.sanity.studio` lewat `sanity deploy` (folder `studio/` di root repo), tidak digabung ke build/deploy situs publik. Satu dataset `production` dipakai, tanpa staging. Semua pengurus aktif mendapat role **Editor** (publish langsung, tanpa gerbang approval); role **Administrator** hanya dipegang maintainer situs. Field yang gagalnya visual/mem-breaking-kan layout (mis. `ratio`/`position`/`span` di galeri) dikurasi lewat pilihan tetap atau dihitung di frontend, bukan bebas diisi pengurus.

**Konsekuensi**: `sourceData.js` bukan lagi satu-satunya Sumber Data — untuk galeri dan artikel, Sanity menggantikan peran itu (lihat entri "Sumber Data" `CONTEXT.md`, disempit oleh ADR ini). Konten lain (`location`, `iqamahOffsets`, tiga pohon silsilah, `donation.qris`/`bank`, dan untuk saat ini `events`/`news`/`programs`/`contact`/`stats`) tetap hand-edited di `sourceData.js`/`location.js` seperti sebelumnya — migrasi dilakukan bertahap per tipe konten, bukan big-bang. Situs publik tetap tidak punya dependency runtime ke Sanity: kalau Sanity down, pengunjung tetap melihat hasil build statis terakhir. Cutover per tipe konten bersifat final — begitu galeri/artikel terverifikasi jalan end-to-end dari Sanity, jalur lama (parser Markdown tangan, field `gallery` di `sourceData.js`) dihapus dari kode, tidak dibiarkan sebagai fallback mati (lihat tiket cutover di `.scratch/cms-migration-sanity/issues/06-cutover-hapus-pipeline-lama.md`).
